# Как запустить и проверить проект на Windows

## 1. Получить именно новую версию

Распакуйте предоставленный архив проекта в удобную папку, например `C:\CAE\Topology-optimization`. В ней должны находиться `README.md`, `requirements-reproduce.txt`, `run_checks.cmd` и папка `topopt`.

Скачайте ZIP основной ветки через GitHub или клонируйте репозиторий:

```powershell
git clone https://github.com/mitjasha/Topology-optimization.git
cd Topology-optimization
```

## 2. Python

Рекомендуется **Python 3.12, 64-bit**, чтобы совпасть с проверенным окружением. Если его нет, установите Windows installer (64-bit) с [официальной страницы Python 3.12.10](https://www.python.org/downloads/release/python-31210/). Это конкретная воспроизводимая версия с установщиком, а не утверждение о последнем security-релизе Python. Установите Python Launcher (`py`). После установки откройте новый PowerShell.

Проверка:

```powershell
py -3.12 --version
```

## 3. Окружение и зависимости

В Проводнике откройте распакованную папку, в адресной строке введите `powershell` и нажмите Enter. В открывшейся консоли выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-reproduce.txt
```

Активация окружения не нужна: все команды явно используют Python из `.venv`. Менять PowerShell ExecutionPolicy не требуется. Основные зависимости — NumPy 2.3.5 и SciPy 1.16.3. При первой установке нужен интернет; для основных расчётов после установки — нет. GPU, Jupyter, платные лицензии и старые `X.npz`/`libtopology` не нужны.

## 4. Быстрый полный запуск

```powershell
.\run_checks.cmd
```

Скрипт последовательно запускает автоматические тесты, ML-бенчмарк и исследование сетки/бинаризации. Он останавливается при программной ошибке и записывает новые результаты в `my_results`, `my_mesh_study`. Проверенные результаты в `results`, `mesh_study` остаются отдельно. Повторный запуск перезаписывает только папки новых результатов.

На используемом при подготовке компьютере эти задачи выполнялись за секунды/десятки секунд; на другом CPU время может заметно отличаться. Матрицы плотные: лучше иметь несколько гигабайт свободной памяти и не увеличивать сетку сверх 48×24 в этом сценарии с плотными матрицами. Команды расширенных экспериментов с разреженным решателем приведены в `docs/development-v2.md`.

Открыть отчёты:

```powershell
Start-Process .\my_results\report.html
Start-Process .\my_mesh_study\report.html
```

Либо откройте эти HTML-файлы двойным щелчком. Не перемещайте HTML отдельно от соседних SVG/CSV/JSON.

## 5. Запуск отдельных шагов

```powershell
# Автоматические проверки численного кода и интерфейсов
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# Набор 24 задач, простая ML-модель и FEM-дооптимизация
.\.venv\Scripts\python.exe -m topopt.benchmark --output my_results

# Сетки 8x4, 16x8, 32x16, 48x24 и бинарная переоценка
.\.venv\Scripts\python.exe -m topopt.mesh_study --output my_mesh_study
```

## 6. Независимая проверка CalculiX — отдельный необязательный шаг

Скачайте [CalculiX 2.23 для Windows с сайта автора](https://www.dhondt.de/calculix_2.23_4win.zip) и распакуйте, например, в `C:\CAE\CalculiX`. Найдите `ccx_static.exe` внутри распакованной папки. Используйте именно фактический путь к файлу:

```powershell
.\.venv\Scripts\python.exe -m topopt.correlation --ccx "C:\CAE\CalculiX\calculix_2.23_4win\ccx_static.exe" --output my_correlation
Start-Process .\my_correlation\report.html
```

Системная установка и добавление CalculiX в PATH не нужны. CalculiX не вложен в архив проекта. Эта команда проверяет три поля плотностей и влияние толщины; это отдельный опыт, а не независимая проверка всех бинарных форм из исследования сетки.

## 7. Что проверять в результатах

- Тесты должны завершиться `OK` (в текущей версии 19 тестов).
- ML-бенчмарк: 14/4/6 случаев в train/validation/test; зеркальные пары находятся в одной части. Численные значения должны быть близки к сохранённым, время может отличаться.
- CalculiX: шесть тонких моделей проходят критерии, три модели большой толщины намеренно оставлены как неуспешные диагностические сравнения. Это не ошибка запуска.
- Сеточный отчёт: отдельно смотрите сплошную модель, неизменное поле плотностей и повторную оптимизацию. Изменение разных конструкций нельзя выдавать за чистую сходимость FEM.
- Бинаризация: `FAIL` означает, что форма не удовлетворяет хотя бы одному заранее указанному критерию. Это допустимый научный результат, а не падение программы. Проверяйте объём, податливость, связность и чувствительность к жёсткости пустоты.
- `converged=False` нельзя трактовать как завершённую оптимизацию.

Исторический notebook 2019 года оставлен для происхождения проекта. Его запуск не входит в эти инструкции. Новый `notebooks/01_benchmark_review.ipynb` — необязательный просмотр сохранённых результатов; для основных опытов Jupyter не нужен.

## Возможные проблемы

**`py` не найден / нет Python 3.12:** установите Launcher/Python, перезапустите PowerShell. Если Python установлен без Launcher, замените `py -3.12` полным путём к своему Python 3.12, например `& "C:\...\python.exe"`.

**`No module named topopt`:** консоль открыта не в корне распакованного проекта. В текущей папке должна быть папка `topopt`.

**`No module named numpy`:** установите зависимости командой из пункта 3 и используйте `.venv\Scripts\python.exe`, а не случайный глобальный Python.

**Ошибка сети при pip:** проверьте доступ к PyPI и настройки proxy вашей организации. Не отключайте TLS-проверку.

**CalculiX не найден:** путь после `--ccx` должен указывать на EXE, не на ZIP или папку. Если путь содержит пробелы, оставьте кавычки.

**Отчёт пустой или с пропавшими изображениями:** убедитесь, что расчёт завершился и HTML открыт вместе со всеми файлами из его папки.

Если возникнет ошибка, сохраните команду и полный текст ошибки. Для сравнения результатов достаточно CSV и `manifest.json` из соответствующей папки.
